## Category codes (from STS 2027 Appendix 4)

| Code | Use | Permitted? | Requirement |
|---|---|---|---|
| `IDEA` | Chatbot as a tool to generate/develop ideas | Yes | Prompt log; citation may be required |
| `CODE` | AI wrote initial code | Yes | **Explicit citation of which portions** + prompt log |
| `STAT` | AI helped identify appropriate statistical tests or tools | Yes | Prompt log. **Interpretation must be the student's** |
| `SUMM` | AI summarized an article *as a starting point before reading it* | Yes | No citation required; the source must actually be read |
| `LANG` | AI sharpened grammar/syntax of student-written text, no new content | Yes | Must be credited; changes minor only |
| `BIB-FMT` | AI fixed structure/formatting of an existing bibliography | Yes | Student verifies every citation |
| ❌ `PROSE` | AI drafted report/abstract/conclusions/future steps | **Never** | — |
| ❌ `BIB-GEN` | AI generated citations or a starter bibliography | **Never** | Fake reference = disqualification |

## Part B — Contemporaneous record (2026-08-02 onward)

### 2026-08-02 — Claim-survival audit of the Π/PID paper
**Tool:** Claude (Anthropic), via Claude Code.
**Categories:** `CODE`, `STAT`, plus verification of existing results.

**What AI was asked to do:** audit the paper's claims against the underlying data; determine which
claims survive; check the current Regeneron STS research-report requirements; design a hardware
validation test; give a go/no-go recommendation.

**What AI actually did:**
- Recovered the deleted simulation-phase tools and result CSVs from git (`bb22d36^`) into a scratch
  directory outside the repository.
- **Wrote ~16 throwaway Python analysis scripts** to recompute published claims from the raw CSVs.
  These were written by AI (`CODE`). They live in a session scratch directory, **not** in this
  repository. **Action required:** any of these whose output is cited in the Research Report must be
  committed here and cited in-text as AI-written code.
- **Selected the statistical tests used in that recomputation** (`STAT`): Spearman and Pearson
  correlation, Wilcoxon signed-rank, sign test, bootstrap confidence intervals (paired difference of
  correlations), OLS with standard errors and CIs, logistic regression with 5-fold stratified
  cross-validated AUC, point-biserial correlation, Wilson-interval reasoning.
- Fetched and summarized the STS 2027 Rules & Entry Instructions and Research Report Guidelines PDFs
  from societyforscience.org (`SUMM`; both documents were then read directly).

**What AI did NOT do:** write any paper prose, abstract, conclusion, or bibliography entry; generate
any citation; decide what the results mean for the project.

**Interpretation and decisions (student's):** which claims to retire, how to reframe the thesis,
whether to submit to STS, and what to fly. Recorded in `DESIGN_LOG.md`.

**Findings that came out of it** (for traceability, not as report text): the n=142 causal
saturation-removal result does not hold; the window-ratio family is invalidated by the project's own
2026-06-22 frozen-Kd test; failure tracks low pitch inertia rather than control authority; the
gain-ceiling and flight-signature results survive.

### 2026-08-02 — Ascent flight firmware: 500 Hz control-loop logging + flight-log reconstruction
**Tool:** Claude (Anthropic), via Claude Code.
**Categories:** `CODE` (firmware + analysis scripts), plus verification of existing results.

**What AI was asked to do:** add a high-rate in-RAM capture of the control loop to
`Firmware/Ascent_TVC/Ascent_TVC.ino` (500 Hz, dumped to `CTL###.CSV` at recovery), mirroring the
existing `captureMotor()`/`dumpMotorLog()` pattern; validate it in the SIL harness with the flight
outcome unchanged; and create a per-flight log covering the flights already flown.

**What AI actually did:**
- **Wrote the instrumentation code in `Ascent_TVC.ino`** (`CODE`) — this is committed flight firmware
  and **must be cited in-text if any number it produces appears in the Research Report**. AI-written
  portions: the `captureControl()` / `dumpControlLog()` block and its `#define` configuration, the
  loop-period histogram and statistics, the two dump call sites, the `cmdX`/`cmdY` hoist inside
  `TVC()`, and the guarded `analogReadResolution`/`analogReadAveraging` lines in `setup()`.
  **No gain, limit, sign, threshold, pyro or recovery logic was altered.**
- Added `inline void analogReadAveraging(int){}` to `Firmware/sim/shims/Arduino.h` (SIL shim, not flight code).
- **Ran the validation, did not assert it:** built the unmodified firmware and the modified firmware in
  the ascent SIL and compared flight outcomes over an 8-case battery, 3 edge cases, and **400 paired
  Monte-Carlo dispersion vectors — 0 differences**. Compiled the real Teensy 4.1 target with
  `arduino-cli` (clean, `--warnings all`) and recorded the RAM/FLASH delta from the actual linker
  output. Disassembled `captureControl` from the ELF to bound its cost by instruction count.
- Wrote **3 throwaway Python analysis scripts** (`CODE`) in a session scratch directory, **not** in this
  repository: a paired SIL equivalence harness, a per-flight fact extractor, and an integral-trim
  residual test. **Action required if cited:** commit and cite them.
- **Wrote `FLIGHT_LOG.md` and `FLIGHT_LOG.csv`** as a lab record, populating the measured columns by
  computing them from the raw SD logs. Fields not supported by data are marked `[CONFIRM]`, unfilled.

**What AI did NOT do:** write any paper prose, abstract, conclusion or bibliography entry; generate any
citation; change any control gain or safety interlock; fly, bench-test, or flash anything; fill in a
flight date, airframe mass/inertia, or outcome that the data does not support.

**Interpretation and decisions (student's):** whether to fly this build; the root cause of ASC036's
logging loss; whether ASC031's firmware provenance changes what the `SERVO_*_SIGN` comment may claim;
all `[CONFIRM]` fields in `FLIGHT_LOG`.

**Findings that came out of it** (traceability, not report text): the abort path previously destroyed
its own control trace (verified — on an aborted SIL case the pre-change binary emitted only
`ASC000.CSV`); ASC036's log stops at burnout with no coast/descent rows and no motor log; ASC031 flew
the pre-2026-07-07-pm firmware, shown independently by ±2 g accelerometer clipping and by a pure-PD
residual test, which means it does not validate the current build's servo sign convention.

**Files touched / code to cite:** `Firmware/Ascent_TVC/Ascent_TVC.ino`, `Firmware/sim/shims/Arduino.h`,
`FLIGHT_LOG.md`, `FLIGHT_LOG.csv`, `DESIGN_LOG.md` (2026-08-02 entry).
